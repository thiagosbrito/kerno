# supabase scope

Root AGENTS.md applies. Versioned, forward-only migrations in `migrations/`; never edit an applied migration, add a new one. Every table in `public` needs RLS enabled, explicit policies and explicit least-privilege grants (default privileges for `anon`/`authenticated` are revoked). Tenant and role decisions come from current `memberships` rows, never from JWT custom claims or `user_metadata`. `SECURITY DEFINER` functions need `set search_path = ''`, an entry in the allowlist in `tests/rls.test.ts` and a justification in the migration. `rollbacks/` holds manual, pre-production undo scripts that are not applied automatically. `seed.sql` holds fake, local-only fixtures applied by `supabase db reset`; never add real data or run it against a hosted project. `pnpm test:db` truncates tenant tables and runs files serially; `db:reset` restores the seed. Rollbacks run newest first. `audit_events` is append-only for every API role and `service_role` (UPDATE/DELETE/TRUNCATE triggers, privileges revoked) and written only by triggers and the definer function `record_audit_event`; new tenant tables need audit triggers or a stated reason ([merchant auth](../docs/security/merchant-auth.md)). Public host resolution is limited to the two `resolve_store_by_*` functions ([host routing](../docs/security/host-routing.md)). Tests run real SQL (PGlite); mocks cannot prove RLS. See [tenancy and RLS](../docs/security/tenancy-and-rls.md).
